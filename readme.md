## 功能需求 
工作中汇报、进度、问题、解决方案 等的上传下达， 工作中的一环。

- proposal.md 的三层结构 模版
  - 第一层： 目标层(Why)
  核心问题： 为什么做该项目？ 旨在解决何种痛点？
  关键内容、项目背景、核心目标、目标用户画像及成功标准
  形象类比： 我们要建造一座什么样的房子？ 供谁居住
  - 第二层： 范围层（What）
  核心问题：具体做什么？不做什么？
  关键内容：功能清单、明确排除项及技术约束
  形象类比：房子有几层？几个房间？是否包含花园？ 
  - 第三层： 验收层 （Done）
  核心问题：怎么判断项目完成了？如何验证交付质量？
  关键内容：可量化的验收标准、性能指标及边界场景测试
  形象类比：房子什么时候竣工? 具体的验收标准是什么？

### 需求文档总结

SDD 工作流的首要步骤 将模糊的需求意图转化为结构化规范。

需求分析的核心任务并非 “穷举所有功能”， 而是促使隐含的决策显性化。每一个 "AI可能产生误解或猜测的环节"，
都应该转化为"人类明确做出的选择"， 包括数据来源， 目标受众， 实现程度以及排除范围。 这些选择被记录在
proposal.md 中， 成为后续所有开发工作的基石与验收标准。

proposal 遵循 “目标层(Why)” -> 范围层（What） -> 验收层(Done) 的三层结构， 三者之间存在严密的逻辑约束关系
目标层界定范围层， 范围层定义验收层，而验收层反向验证目标层的实现程度。

撰写规范时， 对精度的把控是一种需要刻意练习的核心能力：其标准在于 “恰好够AI执行”。

判断这一界限的标准十分明确：

如果某项决策改变了系统的行为， 则需要写入规范；
如果他仅改变代码的编写方式，则由Ai 决定：

AI 严格遵守规范执行，一次到位。

## 架构设计
how    
proposal.md 定义 **做什么**， design.md 定义 **怎么做**

运筹帷幄之中， 决胜千里之外-- 好的架构设计， 往往在落地之前便已奠定胜局。

从proposal.md 到 design.md 关键一步跨越
堪称SDD 全流程中信息密度最高、思想跨度最大的一步。 

先画地图， 再行军

本质并非 “绘制图表” ，而是在编码之前回答一系列关键的**结构性**问题：
系统如何划分、模块间如何通信， 采用何种技术栈及决策依据， 如何保障非功能性要求。 

如果这些问题没有在design.md 中明确， Ai 会猜， 生成代码往往并非我们所愿。

design.md 4 个核心组成部分

- 系统架构
包括模块划分、职责定义、以及数据流向
设计需要遵循**单一职责原则**和关注点分离原理。 

单一职责 一个类只负责一项功能， 只有一个引起它变化的原因。

```py
# 没有遵守单一职责原则， 导致User 类负责了两个功能： 获取用户名和保存用户到数据库。


class User:
    def __init__(self, name):
        self.name = name

    # 职责1 获取用户名
    def get_name(self):
        return self.name

    # 职责2 保存用户到数据库
    def save_to_db(self):
        print("保存用户到数据库")
```

```py
class User
  def __init__(self, name):
    self.name = name
  def get_name(self):
    return self.name

class UserRepository:
  def save(self, user):
    print("保存用户到数据库")
```
## design 的4个核心部分

- 系统架构
  架构方案, 模块划分， 模块职责， 模块间关系
  整体楼的平面图， 几层楼， 每层干什么， 楼梯和电梯在哪？

- 技术选项 (ADR)
每个**关键技术**决策的选项、理由、取舍
为什么用刚结构不用砖混 记录下来， 三年后还能查

- 接口约束 

API 规范 和 数据模型定义
每面墙的承重系数， 每根管道的接口规范 

- 非功能性约束
安全、性能、可运维性、错误处理
消防通道、抗震级别， 防水标准

项目名称：智能日报生成器（AI Daily Report Generator）

项目介绍： 面向日常信息整理与日报编写场景，构建 AI 驱动的智能日报生成工具，旨在降低人工信息收集、内容整理与文档编写成本，提升信息处理效率和日报产出质量。

核心工作与技术亮点：

SDD 规范驱动开发： 采用 Spec-Driven Development（SDD）开发模式，将业务需求拆解为结构化规格、功能模块、开发任务及验收标准，利用 AI 编程工具辅助完成方案设计、代码实现与问题排查，减少需求理解偏差和重复沟通，提升开发效率。

AI 协同研发： 以需求规格和验收标准作为 AI 编码的上下文约束，通过任务拆解、分阶段实现、代码审查与测试验证，形成从需求分析到功能交付的闭环，提升 AI 生成代码的可控性与可维护性。

业务流程自动化： 围绕日报生成的核心流程进行功能设计与模块拆分，减少重复性的信息整理和文档编写工作，提升日报生成的效率与一致性。

质量与可维护性： 注重功能边界、异常场景和输出规范，通过分阶段验证与迭代优化，降低 AI 辅助开发中的实现偏差，提升项目交付质量。
